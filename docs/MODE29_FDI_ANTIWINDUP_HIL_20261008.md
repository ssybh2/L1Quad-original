# Mode29 HIL-only FDI confirmed-severity anti-windup — 2026-10-08

This change lives ONLY in `feature/mode29-fdi-antiwindup-hil-20261008`.
It branches from successful `f31362c` bounded-HIL firmware. It is
**not flight qualified**, especially for motor-fault experiments with
propellers attached. Do not promote to flight without new closed-loop
and estimator validation.

## Observation from Mode29 Log 67
- Injected loss to M1: 70%. Blind FDI confirms close to 69%, then within
  several 400-Hz cycles reaches 100%, followed by a drastic mixer change.
- At 400Hz, the old confirmed update integrates 0.05 x an instantaneous
  normalized residual every 2.5ms. Residual=0.7 means +3.5 percentage
  points per sample. The 0.05 matched-sigma filter takes approximately
  49ms to respond to a motor command transition. This creates short-term
  estimator windup, **even when the initial detection was accurate**.
- In that log, `M29_BALLOC=0` and `M29_PAIR_EN=0`. Thus the bounded
  allocator and new progressive pairing were NOT being exercised.

## HIL-only implementation
Changes are guarded under `M29_BALLOC=1`:
1. Following confirmation, wait 125ms for L1 filtered residual to settle
   after control mixer switching (2.5 effective time constants).
2. Freeze updates if previous bounded allocation failed the requested
   thrust/roll/pitch wrench.
3. Reject physically impossible normalized residuals, weak motor
   commands (<16 in 0..100 motor command scale), poor single-motor fit
   (>0.35), residuals smaller than 3%, or less than six consecutive
   signed-innovation samples.
4. Integrate `delta_pct=clamp(raw_fraction, -0.25,+0.075)`
   percentage points per 400-Hz cycle, i.e. at most +30 pp/s increase
   and -100 pp/s decrease. The physical loss estimate stays [0,100];
   there is no special 70% or 90% override.
5. Keep the existing loss estimation untouched when `M29_BALLOC=0`.
   This maintains compatibility with previous baseline flight firmware
   and exposes an A/B comparison in non-propeller HIL.
6. Record `L1FI` at Mode29 rate:
   - `raw`: signed projection on one-motor failure signature, percent
   - `step`: percentage points integrated this control tick
   - `ratio`: one-motor residual fit (lower better)
   - `w`: nominal command on detected failed motor, [0,100]
   - `gate`: numeric gate code
   - `held`: cumulative cycles blocked
   - `est`: severity estimate in percent

Gate codes: 0 idle, 1 observer settling, 2 primary saturation,
3 invalid/physically impossible residual, 4 excitation too low,
5 poor fit, 6 waiting consistent innovation, 7 deadband,
8 accepted bounded update, 9 synthetic pair/staged recovery,
10 observer gate disabled.

## Important scientific limitations
- The L1 matched-moment uncertainty is not a direct measured
  effectiveness sensor. Model mismatch, actuation delay, external
  disturbances, gyro bias, EKF/NOKOV failure, and saturation can still
  bias the estimated loss.
- 125ms wait is a testable conservative setting, not an identified
  physical motor time constant. The 30 pp/s cap trades faster detection
  for less windup. True 100% loss can be under-estimated while the
  bounded allocator is saturated.
- A false early **motor ID** confirmation is still possible. This change
  only addresses the *post-confirmation loss percentage*.
- Do not claim validated flight control from green CI tests. Full
  actuator-in-loop, timing, state-estimator, and injected/recovered fault
  validation remains required.
